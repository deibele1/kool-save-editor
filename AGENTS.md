# Project notes

- `kse/` and `xoreos-tools/` are untouched reference clones. The project is standalone: it must not build, link or call anything from them.
- Native SwiftUI macOS app, deployment target macOS 14, Swift 6. The app target uses default MainActor isolation; the `KotORKit` package targets are nonisolated and their model types are `Sendable` value types. No external dependencies.
- `KSEMac.xcodeproj` uses filesystem-synchronized groups (objectVersion 77): new files in `KSEMac/` need no project edits. It depends on the local package `KotORKit` (products `Aurora`, `KotORSave`). Bundle ID `Sempervia.KSEMac`, product name “Kool Save Editor” (file, menu bar, window), full name “Kool Save Editor for Macintosh” (About box via `AboutPanel.fullName`, README, NOTICE), module `KSEMac`. Name decision (user): it nods to KSE through its initials without using KSE's name or the KotOR/Star Wars trademarks; renamed from “KotOR Save Editor”. Keep the bundle ID (TCC permission and preferences are tied to it).

## Verification

- Library tests: `cd KotORKit && swift test` (67 tests, ~15 s). Real-save tests read the installed saves (Mac App Store KotOR 1 saves and Steam Cloud TSL saves exist on this machine) and only ever write to temporary copies; set `KSE_TEST_SAVES=<saves folder>` to point at others. `RealGameDataTests` read the Steam TSL install (`…/steamapps/common/Knights of the Old Republic II/KOTOR2.app/Contents/GameData`) and the Mac App Store KotOR 1 install (`/Applications/Knights of the Old Republic.app/Contents/Assets`, installed 2026-10-27) when present.
- App build: `xcodebuild -project KSEMac.xcodeproj -scheme KSEMac -destination 'platform=macOS' -derivedDataPath /tmp/ksemac-dd build`.
- Install for everyday use: `Tools/install-app.sh [folder]` builds a universal Release app and replaces `/Applications/Kool Save Editor.app` (the user runs the installed copy; don't reinstall over it while it is running). It archives and exports with the Developer ID certificate (like `release.sh`, without notarizing): macOS ties the "access data from other apps" permission (Mac App Store saves, TCC service `kTCCServiceSystemPolicyAppDataDetailed`) to the code requirement, and when a differently signed copy (Apple Development) starts, tccd logs "Failed to match existing code requirement" and recreates the entry, turning the user's toggle off. Debug builds are Apple Development signed: only run them with `-KSEMacSavesFolder` so they never touch the App Store containers. Check tccd with `log show --last 30m --predicate 'process == "tccd" AND eventMessage CONTAINS[c] "KSEMac"'`.
- Manual UI checks without touching real saves: `KSE_WRITE_FIXTURE=/tmp/kse-fixture swift test --filter FixtureWriter` (add `KSE_FIXTURE_TSL=1` for a TSL save), then launch the built app with `--args -KSEMacSavesFolder /tmp/kse-fixture/saves -KSEMacGameFolder /tmp/kse-fixture/game`. Debug builds also accept `-KSEMacSection player|npc|party|inventory|journal|globals|versions`, `-KSEMacTab abilities|feats|powers|classes|equipment` and `-KSEMacPicker appearance|portrait|voiceSet` (opens that picker sheet on the General tab) or `-KSEMacPicker items` (with `-KSEMacSection inventory`: opens Add Items).
- The user may be using a running app instance; use a separate derived-data folder and don't kill their instance. For UI-only changes, build and ask the user to try it before writing UI tests.

## UI notes

- Never put `Text(...).fixedSize(horizontal: false, vertical: true)` above a `Table` in the split-view detail: on macOS 27 it broke layout of the whole window (blank sidebar and outline, empty placeholder rows, "Invalid view geometry: width is negative" in the log). Explanatory text goes below tables as a plain caption.
- Layout (user-approved): three columns (saves sidebar | section outline in `.listStyle(.sidebar)` | detail), window title and subtitle in the toolbar above the outline. The title bar is ONE opaque, two-toned strip across the whole top of the window (user requirements: content must not scroll under the window buttons; two tones; contrast with the sidebar): gray `Color.titleBarSidebar` above the saves sidebar (width = the sidebar's measured right edge, 0 when it is hidden) and dark `Color.titleBarMain` (window background) to the right. It is a single overlay on the NavigationSplitView (hit testing off, ignoring safe areas) with height from `TitleBarHeightReader` (window content height minus `contentLayoutRect`), because on macOS 27: `toolbarBackground` can't color the area above the floating glass sidebar, split-view columns report no top safe-area inset, and per-column strips let the 1 px column divider show through the title. Colors inside the glass window render a bit lighter than specified (sRGB 0.255 shows as #525252). Rejected: translucent glass bar, same background for both columns (divider cut the title), a two-column sidebar with a header row ("much much worse").
- Outline icons are tinted explicitly (`.foregroundStyle(.tint)`), and the outline scrolls the selected section into view.
- A save folder that can't be read shows a short message ("Access blocked by macOS") with a `HelpLink` ? button (user requirement: a button, not only a tooltip). It opens a sheet, not a popover, so the steps stay visible while the user is in System Settings: on macOS 27 Files & Folders › Kool Save Editor › <game> (confirmed by the user), on earlier versions Full Disk Access (works everywhere; don't give macOS 27 steps to older systems). The permission only reaches a new process, so the sheet offers Quit & Reopen (`AppDelegate.relaunchesAfterQuit`; the sheet must be dismissed before `NSApp.terminate`, or AppKit just beeps); Refresh is offered for other read errors.
- To check screens without touching the user's running copy: launch the Debug binary directly (not `open`), capture its window by PID with `screencapture -l<windowID>`, then kill that PID only. Use copies of saves in /tmp with `-KSEMacSavesFolder`.

## Design notes

- Formats (`Aurora`) are Swift ports of xoreos-tools with fixes: bit-exact GFF round trips (raw string bytes, float bit patterns, field order, struct IDs), bounds/recursion checks, code-page strings, ERF rewrites that keep the original header and resource IDs, lazy memory-mapped BIF/TLK/texture packs, top-down RGBA output for TPC/TGA. Unneeded formats (GFF4, ERF V2+, NWN/Dragon Age/Witcher specifics, XML) were left out.
- Save locations: KotOR 1 App Store `~/Library/Containers/com.aspyr.kotor/Data/Library/Application Support/Knights of the Old Republic/saves`; Steam `~/Library/Application Support/<game>/saves`. TSL Steam with `Use Steam Cloud=1` (swkotor2.ini) saves to `<Steam library>/steamapps/common/Knights of the Old Republic II/cloudsaves/<account>/`, next to KOTOR2.app, NOT under Application Support; Steam libraries come from `steamapps/libraryfolders.vdf`.
- GFF values compare by bit pattern (custom `GFFValue ==`): real TSL area files hold signaling-NaN floats, and IEEE `==` made unchanged documents look edited.
- A save is savenfo.res, PARTYTABLE.res, GLOBALVARS.res, Screen.tga and SAVEGAME.sav (ERF with INVENTORY.res, AVAILNPC<n>.utc and one nested ERF per module; the player is `Mod_PlayerList[0]` in Module.ifo of the LASTMODULE). File lookups are case-insensitive. Only files whose parsed contents changed are re-encoded.
- KSE behaviours kept on purpose: setting base HP/FP also refills current HP/FP; party max two companions; occupied equipment slots keep their ObjectId. Fixes relative to KSE are listed in the headers of `Creature.swift`, `SaveGame+Editing.swift` and `ItemFactory.swift` (index-based inventory edits, PT_NUM_MEMBERS/PT_PLAYEDSECONDS/PCNAME/Mod_FirstName kept in sync, no TSL fields on KotOR items, working Jedi→non-Jedi class change, Force Points no longer corrupting field 0).
- New object IDs (equipping into an empty slot) come from Module.ifo's `Mod_NextObjId0`, which is then incremented. Unequipping clears matching `CombatInfo` Left/RightEquip references.
- Voice sets (UI "Voice set" = `SoundSetFile`, a soundset.2da row): the games give the player row 83 (female) or 85 (male) at creation, and the exact rows matter (`GameData.playerSoundsets`). KotOR 1's table has them (Player_Female_W/Player_Male_W); TSL's stops at row 65, so the TSL player is silent (its recordings p_plyerfw/p_plyermw are in sounds.bif but there are no SSFs) and the editor lists 83/85 as silent, not-in-table entries; mods (e.g. JC's Player Soundset Restoration) add them in Override. Row 0 is "None"; 0xFFFF is shown as "Not set". Names come from the `strref` column with "**Do Not Translate This**" stripped. Several TSL saves here had their gender changed by the user (they started female): don't infer engine behaviour from their Gender field.
- Voice samples: SSF V1.1 (KotOR uses the first 28 of 40 slots) → talk table sound resref (only with flag 2) → Override, StreamSounds/StreamWaves/StreamVoice, then BIF WAV. StreamSounds WAVs hide behind a 470-byte fake MP3 frame; voice over/music are MP3 behind a WAV header with an empty data chunk (`GameSound.playable`); playback is `AVAudioPlayer` (`VoicePlayer`). The 2DA data-size field is ignored (some modding tools store 0).
- Appearance previews are headshots: `appearancePortraits` from portraits.2da `appearancenumber`/`appearance_s`/`appearance_l`, plus name matching for `Party_NPC_<name>` → `po_p<name>` and P_* bodies of another size. Some TSL portrait rows name textures that don't exist (po_pfhc4, K1 companions), so a placeholder there is expected. A 3D model preview was not attempted.
- Item catalog (add/equip pickers) must include ALL items (user requirement): every UTI in the BIFs, the override folder (replaces BIF blueprints of the same name) and the level files (`Modules/*.rim|mod|erf`, KotOR's `rims/`, read with `RIMIndex`/`ERFIndex` via `openArchiveIndex`). Level copies are deduplicated by `GameAssets.signature` (displayed name, tag and every field except price, descriptions, plot/stolen/identified flags, stack size and comments), keeping variants that reuse a name for a different item: TSL 1132 items (138 from modules, e.g. Freedon Nadd's Blade), KotOR 1 841 (284). Module entries carry `archive` (id `resref@file`, Source column shows the module) and load through `itemTemplate(_ template:)`; the plot flag shows as a "Quest" badge. Text in `{curly braces}` is hidden everywhere (`GameData.displayed`), as the games do: TSL names items like "{02}Padawan Robe". `<FullName>`/`<PlayerName>`/`<FirstName>`/`<LastName>` (TSL item names, descriptions, journal) are filled in with the save's player name (`SaveDocument.textTokens` → `TextTokens.apply`; user requirement); tokens set while playing (`<CUSTOM0>`, `<blbutton>`) stay. TSL has no Revan's robes ("Darth Revan's Robes" in its dialog.tlk is a KotOR 1 leftover); KotOR 1's is `g_a_mstrrobe06`, base item Revan_Armor (label fallbacks show underscores as spaces). Picker and inventory searches use `SearchText` (all words, ignoring case, accents, apostrophes and a plural "s"). KotOR 1 App Store's `Patch.erf` (patched skills.2da, GUIs, player textures) isn't read.
- Influence (TSL only; KotOR 1 has no influence system) lives in `PT_INFLUENCE[npc].PT_NPC_INFLUENCE`; missing entries are created at 50 so every companion can be edited.
- Versions: `SaveVersionStore` snapshots into `~/Library/Application Support/KSEMac/Versions/<game folder> – <save> [hash]/<timestamp>/` with a `version.json` manifest (sizes, SHA-256). `SaveWriter.commit` validates output, snapshots, writes atomically (temp file + rename), reads back and reloads, and restores the snapshot on any failure. Restores verify the snapshot, snapshot the current state (refusing to restore if that fails), then restore.
- Version history (user requirements): oldest first, starting with the original. Columns Version | Changes | Played | Saved | Size. Playing the game also rewrites saves, so versions are kept across game saves; "Played" is the change in savenfo.res TIMEPLAYED since the previous row, always signed ("+0m", "−1h 12m" after restoring an older version); the first row (the original) shows its total play time instead (user requirement). `timePlayed` is recorded per version and read from the kept savenfo.res for older manifests; `playTimeDeltas()`. When the save changed after the editor's last write, Changes reads "<edits>, then played" if TIMEPLAYED went up, else "<edits>, then changed outside the editor". Versions are numbered (`number`: 1 = "Original", then "Version N"); `changes` says how a version differs from the previous one: "None" for the original (and for a rolled-back save), the edits saved (no "After:" prefix), "Restored <title>" (`restoringNumber`), or "Changed outside the editor" (files differ from the previous operation's recorded `result`, e.g. the game saved over the slot). `result` (file digests after the save/restore) is recorded once the operation succeeds. The table ends with a non-restorable "Current save" row from `currentState(of:)`. Pruning always keeps the original. Manifests from earlier builds (no labels, or `state` strings like "After: …") get numbers and changes derived in `versions(for:)`.

## Distribution

- License decision (user, 2026-10-26): the app stays GPL v3 or later (required: KSE and xoreos-tools are both GPLv3+ and the Swift code is a translation of theirs), with a prominent disclaimer: derived from GPL software, NO COPYRIGHT CLAIMED by the maintainer (most new code is AI-written; upstream copyrights stay with their authors), NO WARRANTY and NO LIABILITY (including lost saves), not affiliated (trademarks). The wording lives in `NOTICE` (canonical), the README "License and disclaimer" section and `KSEMac/AboutPanel.swift` (About box credits); keep them in sync. `LICENSE` and `NOTICE` are bundled into the app as resources (explicit file references in the project, outside the synchronized `KSEMac/` group) and linked from the About box. The Info.plist copyright line reads "No copyright claimed. Derived from KSE and xoreos-tools; GNU GPL v3 or later. No warranty." Do not add a copyright line for the user.
- Still required when releasing: publish the complete source for each release (public repo with a tag matching each binary; the folder is not a git repo yet), ship `LICENSE`/`NOTICE` in the download too, and add the source URL to the About box once it exists. No Mac App Store (its terms add restrictions; the copyrights aren't the user's).
- Trademarks/content: don't imply endorsement (keep the disclaimer); the product name avoids the game trademarks ("Kool Save Editor for Macintosh"; "for Macintosh" is a referential phrase like Apple's allowed "for Mac"); the icon is original; ship no game files; keep the `kse/` and `xoreos-tools/` clones out of the published repo (already gitignored; kse contains a Boba Fett icon).
- macOS: the keychain has a "Developer ID Application (QFY7385FUG)" certificate. `Tools/release.sh` archives the universal Release build, exports it with Developer ID (verified: hardened runtime, secure timestamp), notarizes and staples the app, builds `build/Kool-Save-Editor-<version>.dmg` (app, Applications link, LICENSE, NOTICE), signs, notarizes and staples the DMG, and checks both with `spctl`. Notarization needs the keychain profile `KSEMac` (user runs `xcrun notarytool store-credentials KSEMac --apple-id <Apple ID> --team-id QFY7385FUG`; never handle the password). Publish on GitHub Releases (optionally DeadlyStream / a Homebrew cask).
- Published: public repo https://github.com/deibele1/kool-save-editor (branch `main`, gh account `deibele1`); its URL is in the About box (`AboutPanel.sourceURL`), README and NOTICE. Releases: tag `v<version>` on the released commit, `Tools/release.sh`, then `gh release create` with the DMG. Bump MARKETING_VERSION/CURRENT_PROJECT_VERSION for each release. Debug builds accept `-KSEMacShowAbout YES` (with `-KSEMacSavesFolder`) to open the About box for screenshots.
